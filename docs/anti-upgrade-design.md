# Anti-upgrade design principles

This site should help the owner evaluate device needs without exaggerating certainty.

## Rules

1. User-provided configuration is the source of truth for the owned device.
2. Public specifications may enrich a product profile, but uncertain sub-model details must be omitted.
3. Do not state that an upgrade is unnecessary unless a concrete requirement and evidence support that conclusion.
4. Prefer neutral wording such as "no documented blocker yet", "needs more evidence", or "re-evaluate after observation".
5. Never invent purchase price, purchase date, usage time, battery health, benchmark results, or daily cost.
6. Capability coverage describes what the collection can plausibly support based on known hardware categories/specs; it is not a guarantee of performance.
7. Wishlist items should use a cooling-off period before being framed as purchase candidates.
